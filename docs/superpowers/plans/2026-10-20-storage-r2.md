# Módulo storage (URLs firmadas R2) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dar al backend la capacidad de emitir URLs firmadas de subida privada a Cloudflare R2 para comprobantes de pago, con validación de tipo MIME y tamaño antes de firmar, expuesta como `POST /orders/:id/payment/upload-url`.

**Architecture:** Nuevo módulo `storage` con un `StorageService` que envuelve `@aws-sdk/client-s3` (R2 es S3-compatible) y firma `PutObjectCommand` con `@aws-sdk/s3-request-presigner`. El firmado es **100% local** (no hace ninguna llamada de red: calcula una firma SigV4), así que funciona igual en dev, test y prod sin necesitar un R2 real ni un mock como MinIO — las pruebas usan credenciales de R2 ficticias. `OrdersModule` importa `StorageModule` y expone el endpoint; el pedido debe ser del cliente y estar `PENDING_PAYMENT`. La validación "real" de tipo/tamaño ocurre aquí, antes de firmar, sobre lo que el cliente declara (`contentType`, `fileSizeBytes`); el módulo `payments` (siguiente tarea de Sprint 2, fuera de este plan) hará `POST /orders/:id/payment` con el `proofKey` resultante y el bloqueo de duplicados (D21/D64) — este plan **no** lo implementa.

**Tech Stack:** NestJS 11, TypeORM 0.3, `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` (nuevas dependencias), Jest + Supertest (e2e contra Postgres/Redis reales de `licencias_test`, igual que el resto del backend).

**Spec:** `docs/03-requerimientos-no-funcionales.md` (RNF-SEG-09), `docs/02-requerimientos-funcionales.md` (RF-COM-04), `docs/06-api.md` (fila `POST /orders/:id/payment/upload-url`), `docs/04-arquitectura.md` (R2 en el diagrama y en despliegue, D48/D49), `docs/09-decisiones-y-preguntas-abiertas.md` (D70, nueva en este plan).

## Global Constraints

- Entidades, rutas y código en **inglés**; mensajes al usuario y documentación en **español**.
- DTOs con `class-validator` (whitelist ya activado globalmente en `main.ts`/`configure-app.ts`).
- Tipos usados solo como tipo van con `import type` — **excepto** un tipo usado como el tipo de un parámetro de constructor de una clase con DI (`@Injectable()`): ese va como import de valor normal (`emitDecoratorMetadata` lo necesita). `ConfigService` y `StorageService` se inyectan por constructor → import de valor normal. `AllowedProofMimeType`, `AuthenticatedUser`, `EnvironmentVariables` se usan solo como tipo → `import type`.
- Cambios de esquema = migración; **este plan no cambia el esquema** (la tabla `payments` con `proofKey`/`proofHash` ya existe desde Sprint 1).
- Autorización por rol y por propiedad: un pedido ajeno responde 404 igual que uno inexistente (regla 7, mismo patrón que `OrdersService.findOwned`).
- No inventar datos de negocio: el tamaño máximo (5 MB) y los tipos permitidos (JPG/PNG/PDF) ya fueron decididos con el usuario y quedan registrados como D70 — no son un placeholder.
- Firmar una URL de subida **no** es una mutación crítica (no toca la base de datos): no requiere `audit_logs`. La auditoría del comprobante llega con el módulo `payments` (al registrar el pago).
- `npm run typecheck && npm test && npm run test:e2e` deben pasar en verde al final de cada tarea.

```typescript
import { PutObjectCommand, S3Client } from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';
import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { randomUUID } from 'node:crypto';
import type { EnvironmentVariables } from '../core/config/env.validation';
import {
  ALLOWED_PROOF_MIME_TYPES,
  UPLOAD_URL_TTL_SECONDS,
} from './storage.constants';
import type { AllowedProofMimeType } from './storage.constants';

export interface ProofUploadUrl {
  uploadUrl: string;
  proofKey: string;
}

@Injectable()
export class StorageService {
  private readonly client: S3Client;
  private readonly bucket: string;

  constructor(config: ConfigService<EnvironmentVariables, true>) {
    const accountId = config.get('R2_ACCOUNT_ID', { infer: true });
    this.bucket = config.get('R2_BUCKET', { infer: true });
    this.client = new S3Client({
      region: 'auto',
      endpoint: `https://${accountId}.r2.cloudflarestorage.com`,
      credentials: {
        accessKeyId: config.get('R2_ACCESS_KEY_ID', { infer: true }),
        secretAccessKey: config.get('R2_SECRET_ACCESS_KEY', { infer: true }),
      },
    });
  }

  /**
   * Firma una URL de subida privada para un comprobante de pago (RNF-SEG-09).
   * El tipo y el tamaño ya se validaron en el DTO; al firmar con `ContentType`,
   * R2 exige que la subida real use el mismo header `Content-Type`.
   */
  async createProofUploadUrl(
    orderId: string,
    contentType: AllowedProofMimeType,
  ): Promise<ProofUploadUrl> {
    const ext = ALLOWED_PROOF_MIME_TYPES[contentType];
    const proofKey = `proofs/${orderId}/${randomUUID()}.${ext}`;
    const command = new PutObjectCommand({
      Bucket: this.bucket,
      Key: proofKey,
      ContentType: contentType,
    });
    const uploadUrl = await getSignedUrl(this.client, command, {
      expiresIn: UPLOAD_URL_TTL_SECONDS,
    });
    return { uploadUrl, proofKey };
  }
}
```

  /** Solo mientras el pedido sigue PENDING_PAYMENT; no es una mutación (no hay auditoría, RNF-SEG-09). */
  async requestPaymentUploadUrl(
    user: AuthenticatedUser,
    orderId: string,
    dto: CreateUploadUrlDto,
  ): Promise<UploadUrlResponseDto> {
    const order = await this.findOwned(user.id, orderId);
    if (order.status !== OrderStatus.PENDING_PAYMENT) {
      throw new ConflictException(
        'Solo puedes subir el comprobante mientras el pedido está pendiente de pago',
      );
    }
    const { uploadUrl, proofKey } = await this.storage.createProofUploadUrl(
      order.id,
      dto.contentType,
    );
    return UploadUrlResponseDto.from(uploadUrl, proofKey);
  }
