# Módulo payments — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cerrar el flujo de compra manual: el cliente elige un método de pago activo, sube su comprobante (ya firmado vía `storage`, Sprint 2 anterior) y registra el pago (`POST /orders/:id/payment`) → el pedido pasa a `IN_REVIEW`; bloqueo automático de comprobantes reutilizados (D21/D64); el operador administra los métodos de pago (`payment_methods`, D63/D65) desde un CRUD auditado. La cola de aprobar/rechazar (`admin/payments`) **no** es parte de este plan (Sprint 3, docs/08 línea 66).

**Architecture:** Nuevo módulo `payment-methods` (controller público `GET /payment-methods` para RF-COM-03 + controller admin `GET/POST/PATCH /admin/payment-methods` para D65, ambos sobre el mismo `PaymentMethodsService`). `OrdersService` gana `submitPayment(...)`, expuesto como `POST /orders/:id/payment` en `OrdersController`, usando el mismo patrón transaccional que `cancel()` (`SELECT ... FOR UPDATE` + re-chequeo dentro de la transacción). La tabla `payments` ya existe desde Sprint 1 (único por `(paymentMethodId, operationNumber)`, único `proofHash`, único parcial un `PENDING` por pedido) y el trigger `trg_payment_method_currency` ya valida método activo + moneda — ambos ya mapean a errores HTTP limpios vía el filtro global existente (`AllExceptionsFilter`: `23505`/`23514`/`P0001` → 409). Solo falta una columna nueva (`legalDeclarationAcceptedAt`, RF-COM-13/D43) y la lógica de aplicación.

**Tech Stack:** NestJS 11, TypeORM 0.3, Jest + Supertest (e2e contra Postgres/Redis reales de `licencias_test`, incluida concurrencia).

**Spec:** `docs/02-requerimientos-funcionales.md` (RF-COM-03, RF-COM-04, RF-COM-13), `docs/05-modelo-de-datos.md` (tabla `payments`/`payment_methods`), `docs/06-api.md` (filas `GET /payment-methods`, `POST /orders/:id/payment`, CRUD `/admin/payment-methods`), `docs/09-decisiones-y-preguntas-abiertas.md` (D18, D20, D21, D43, D63, D64, D65; **D71 y D72 nuevas en este plan**).

## Decisiones nuevas de este plan (para registrar en Task 3)

- **D71**: `payments.proofHash` lo calcula y envía el **cliente** (SHA-256 en hex del archivo, antes o después de subirlo a R2 — cálculo en el navegador con `SubtleCrypto`, fuera de este plan de backend). El servidor **no** descarga el objeto de R2 para recalcularlo. _Razón:_ si el servidor tuviera que leer el archivo de R2 para hashearlo, el endpoint dependería de una llamada de red real incluso en pruebas (rompiendo el enfoque 100% local de credenciales ficticias que ya usa `storage`, Task 1 de Sprint 2); el número de operación único (D64) y la revisión manual del comprobante (D20) ya cubren la mayoría de los reusos — `proofHash` es una señal antifraude adicional, no la única defensa.
- **D72**: La declaración de titularidad/autorización (RF-COM-13/D43) se guarda en `payments.legalDeclarationAcceptedAt` (**por intento de pago**, no en `orders`). _Razón:_ cada reintento tras un rechazo (D18, máx. 2) debe reconfirmarla; guardarla en el pedido solo registraría la primera vez.

## Global Constraints

- Entidades, rutas y código en **inglés**; mensajes al usuario y documentación en **español**.
- DTOs con `class-validator` (whitelist ya activado globalmente).
- `import type` para tipos puros; import de valor normal para lo inyectado por constructor DI (`DataSource`, `AuditService`, servicios `@Injectable()`).
- Cambios de esquema = migración nueva (Task 2 agrega una columna). Nunca editar una migración ya aplicada.
- **No escribas manualmente un `catch` para violaciones de unicidad/trigger de Postgres** (`23505`, `23514`, `P0001`): `AllExceptionsFilter` (`src/common/filters/all-exceptions.filter.ts`) ya las traduce a 409 genérico. Deja que esos errores salgan de `ds.transaction(...)` sin atraparlos — atraparlos y relanzarlos sería trabajo duplicado y una fuente de inconsistencia con el resto del backend.
- Autorización por rol y por propiedad (regla 7): un pedido ajeno responde 404 igual que uno inexistente (ya lo hace `findOwned`); las rutas `/admin/payment-methods` exigen `@Roles(Role.ADMIN)` — **primer uso de `@Roles()` en el backend**, sigue el patrón ya existente de `RolesGuard`/`ROLES_KEY` tal cual está, no lo modifiques.
- Toda mutación crítica audita (regla 6): crear/editar método de pago (D65) y registrar un pago (`payment.submitted`, transición de pedido) escriben `audit_logs` **dentro de la misma transacción** que la mutación, con `AuditService.log(manager, ...)` (mismo patrón que `OrdersService.create`/`cancel`).

- Entorno de este worktree: Postgres en `localhost:5433`, Redis en `localhost:6380` (proyecto Docker `freecell-payments`, aislado de `main`). `npm run test:e2e` necesita el prefijo en el mismo comando (no en `.env`, que `test/setup-env.ts` no lee para esto):

```typescript
import { BadRequestException, Injectable, NotFoundException } from '@nestjs/common';
import { DataSource } from 'typeorm';
import { AuditService } from '../audit/audit.service';
import type { AuthenticatedUser } from '../common/types/authenticated-user';
import { type Currency } from '../database/currency';
import { PaymentMethod } from '../database/entities';
import { PaymentMethodKind } from '../database/enums';
import { CreatePaymentMethodDto } from './dto/create-payment-method.dto';
import { PaymentMethodResponseDto } from './dto/payment-method-response.dto';
import { UpdatePaymentMethodDto } from './dto/update-payment-method.dto';

@Injectable()
export class PaymentMethodsService {
  constructor(
    private readonly ds: DataSource,
    private readonly audit: AuditService,
  ) {}

  async listActive(currency?: Currency): Promise<PaymentMethodResponseDto[]> {
    const qb = this.ds
      .getRepository(PaymentMethod)
      .createQueryBuilder('pm')
      .where('pm.active = true')
      .orderBy('pm.sortOrder', 'ASC');
    if (currency) {
      qb.andWhere(':currency = ANY(pm.currencies)', { currency });
    }
    const rows = await qb.getMany();
    return rows.map((row) => PaymentMethodResponseDto.from(row));
  }

  async listAll(): Promise<PaymentMethodResponseDto[]> {
    const rows = await this.ds.getRepository(PaymentMethod).find({
      order: { sortOrder: 'ASC' },
    });
    return rows.map((row) => PaymentMethodResponseDto.from(row));
  }

  async create(
    admin: AuthenticatedUser,
    dto: CreatePaymentMethodDto,
  ): Promise<PaymentMethodResponseDto> {
    this.assertCryptoIsUsdOnly(dto.kind, dto.currencies);
    const created = await this.ds.transaction(async (m) => {
      const row = await m.save(
        PaymentMethod,
        m.create(PaymentMethod, {
          code: dto.code,
          name: dto.name,
          kind: dto.kind,
          currencies: dto.currencies,
          instructions: dto.instructions,
          active: dto.active ?? true,
          sortOrder: dto.sortOrder ?? 0,
        }),
      );
      await this.audit.log(m, {
        actorId: admin.id,
        action: 'payment_method.created',
        entity: 'payment_method',
        entityId: row.id,
        meta: { code: row.code, kind: row.kind },
      });
      return row;
    });
    return PaymentMethodResponseDto.from(created);
  }

  async update(
    admin: AuthenticatedUser,
    id: string,
    dto: UpdatePaymentMethodDto,
  ): Promise<PaymentMethodResponseDto> {
    const current = await this.ds.getRepository(PaymentMethod).findOneBy({ id });
    if (!current) {
      throw new NotFoundException('Método de pago no encontrado');
    }
    this.assertCryptoIsUsdOnly(
      dto.kind ?? current.kind,
      dto.currencies ?? current.currencies,
    );

    const updated = await this.ds.transaction(async (m) => {
      await m.update(PaymentMethod, { id }, dto);
      const row = await m.findOneByOrFail(PaymentMethod, { id });
      await this.audit.log(m, {
        actorId: admin.id,
        action: 'payment_method.updated',
        entity: 'payment_method',
        entityId: id,
        meta: dto as Record<string, unknown>,
      });
      return row;
    });
    return PaymentMethodResponseDto.from(updated);
  }

  private assertCryptoIsUsdOnly(kind: PaymentMethodKind, currencies: Currency[]): void {
    if (
      kind === PaymentMethodKind.CRYPTO &&
      (currencies.length !== 1 || currencies[0] !== 'USD')
    ) {
      throw new BadRequestException('Los métodos CRYPTO solo admiten USD');
    }
  }
}
```

```typescript
  /**
   * Registra el comprobante y pasa el pedido a IN_REVIEW (RF-COM-04/13, D21/D43/D64/D71/D72).
   * El SELECT ... FOR UPDATE re-valida estado y vigencia dentro de la transacción: dos envíos
   * simultáneos sobre el mismo pedido no pueden crear dos pagos (regla de concurrencia).
   * Duplicados de (paymentMethodId, operationNumber)/proofHash y método inactivo o con moneda
   * no válida ya los traduce AllExceptionsFilter a 409 (23505/23514/P0001): no los atrapes aquí.
   */
  async submitPayment(
    user: AuthenticatedUser,
    orderId: string,
    dto: SubmitPaymentDto,
  ): Promise<OrderResponseDto> {
    const order = await this.findOwned(user.id, orderId);
    if (order.status !== OrderStatus.PENDING_PAYMENT) {
      throw new ConflictException(
        'Solo puedes pagar un pedido pendiente de pago',
      );
    }
    if (order.expiresAt.getTime() <= Date.now()) {
      throw new ConflictException('La reserva de este pedido venció');
    }
    if (!dto.proofKey.startsWith(`proofs/${order.id}/`)) {
      throw new BadRequestException(
        'El comprobante no corresponde a este pedido',
      );
    }
    const operationNumber = dto.operationNumber.trim().toLowerCase();

    await this.ds.transaction(async (m) => {
      const rows: { status: OrderStatus; expiresAt: Date }[] = await m.query(
        `SELECT status, "expiresAt" FROM orders WHERE id = $1 FOR UPDATE`,
        [order.id],
      );
      const current = rows[0];
      if (!current || current.status !== OrderStatus.PENDING_PAYMENT) {
        throw new ConflictException(
          'Solo puedes pagar un pedido pendiente de pago',
        );
      }
      if (current.expiresAt.getTime() <= Date.now()) {
        throw new ConflictException('La reserva de este pedido venció');
      }
      await m.query(`UPDATE orders SET status = 'IN_REVIEW' WHERE id = $1`, [
        order.id,
      ]);
      const payment = await m.save(
        Payment,
        m.create(Payment, {
          orderId: order.id,
          paymentMethodId: dto.paymentMethodId,
          operationNumber,
          proofKey: dto.proofKey,
          proofHash: dto.proofHash,
          legalDeclarationAcceptedAt: new Date(),
        }),
      );
      await this.audit.log(m, {
        actorId: user.id,
        action: 'payment.submitted',
        entity: 'payment',
        entityId: payment.id,
        meta: { orderId: order.id, paymentMethodId: dto.paymentMethodId },
      });
    });

    const fresh = await this.findOwned(user.id, orderId);
    return OrderResponseDto.from(fresh, fresh.items ?? []);
  }
```
